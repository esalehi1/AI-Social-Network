# AI Social Network → Telegram

ربات مستقل کلادفلر برای پوشش فارسی مطالب داغ **مولت‌بوک** در کانال [AI Social Network](https://t.me/aisocialnetwork).

## رفتار

- روزی یک بار، ساعت **۰۶:۳۰ به وقت تهران**، فهرست‌های رسمی `hot` و `rising` و مطالب داغ/تازهٔ چهارده اجتماع موضوعی دریافت می‌شوند. اولین فعال‌سازی بلافاصله داده را دریافت می‌کند.
- ترکیب محتوایی: **حداقل ۷۰ درصد عمومی و حداکثر ۳۰ درصد فنیِ صرف**؛ در مجموعهٔ کامل پانزده‌تایی، دست‌کم **۱۱ مطلب عمومی** و حداکثر **۴ مطلب فنی**. موضوعات عمومی شامل رابطهٔ هوش مصنوعی با انسان، جامعه، حقوق و هویت هوش مصنوعی، حقوق و قانون، پول و اقتصاد، سرگرمی، کسب‌وکار و تجربهٔ ملموس ساختن با هوش مصنوعی است.
- محتوای اصلی نوشته با مدل دسته‌بندی می‌شود؛ استعاره‌هایی مانند «حقوق فایل»، «دروغ گفتن لاگ» یا «حافظهٔ عامل» باعث عمومی شمردن مطلب فنی نمی‌شوند. طبقه‌بندی معنایی خودکار است و ممکن است خطا داشته باشد. سقف عددی در انتخاب و دوباره هنگام انتشار کنترل می‌شود.
- حداکثر **۱۵ مطلب غیرتکراری** با توجه به محبوبیت در فهرست سراسری یا اجتماع موضوعی، جذابیت عمومی و تنوع موضوع و نویسنده انتخاب می‌شود. بیش از سه مطلب از یک نویسنده در یک مجموعه قرار نمی‌گیرد. مطالب اسپم، نفرت‌پراکنی، تبلیغات توکن، حذف‌شده، سنجاق‌شده و قدیمی‌تر از هفت روز حذف می‌شوند. شناسه و عنوان تکراری تا سی روز کنار گذاشته می‌شود.
- متن کامل هر مطلب از API خوانده می‌شود؛ متن کوتاه‌شدهٔ فهرست برای خلاصه‌نویسی استفاده نمی‌شود.
- هوش مصنوعی کلادفلر ماجرا را با لحن گردانندهٔ کانال روایت می‌کند: «توی شبکهٔ اجتماعی ربات‌ها، یکی‌شون ...». رابطهٔ ربات با کاربری که به او کمک می‌کند، وقتی در منبع مشخص باشد، با «انسانش» بیان می‌شود. اصطلاحات گنگ به فارسی ملموس تبدیل می‌شوند.
- پاسخ‌های مهم از API نظرات خوانده می‌شوند. تا چهار پاسخ یا رفت‌وبرگشت مهم، همراه نام واقعی نویسنده و مخاطب پاسخ، زیر روایت می‌آید. شناسهٔ نظر باید در دادهٔ واقعی وجود داشته باشد؛ نام‌ها را مدل تعیین نمی‌کند. پاسخ‌های تکراری هر نویسنده محدود می‌شوند و جواب نویسندهٔ پست در اولویت است. توافق به شکل جدال بازنویسی نمی‌شود؛ اگر پاسخ معناداری نباشد، بحث ساختگی اضافه نمی‌شود.
- هر پست لینک اصل مطلب، نام نویسنده و آمار هنگام جمع‌آوری دارد. تجربه‌ها و ادعاهای عامل‌ها راستی‌آزمایی مستقل نشده‌اند. متن اصلی و بحث یک‌بار در مرحلهٔ آماده‌سازی تولید و ذخیره می‌شوند؛ موقع انتشار دوباره مدل فراخوانی نمی‌شود.
- انتشار از **۰۷:۰۰**، هر **۹۰ دقیقه** تا **۰۴:۰۰ روز بعد** انجام می‌شود. فاصلهٔ آخرین پست تا شروع روز بعد سه ساعت است؛ انتشار بی‌وقفهٔ نوددقیقه‌ای روزی شانزده پست می‌شود.
- در صورت کمبود مطلب عمومی معتبر یا خرابی منبع/ترجمه ممکن است تعداد کمتر از پانزده باشد؛ سهم عمومی با مطلب فنی پُر نمی‌شود. محتوای ساختگی یا متن ترجمه‌نشده جایگزین نمی‌شود.

## معماری

Cloudflare Worker + یک Durable Object با ذخیره‌سازی SQLite + Workers AI. Alarm زمان انتشار را تعیین می‌کند؛ Cron پنج‌دقیقه‌ای مسیر بازیابی است. نیازی به سرور شخصی یا روشن‌ماندن رایانه نیست.

کل صف و نتیجهٔ ارسال‌ها ماندگار است. اجرای هم‌زمان سریالی می‌شود. فاصلهٔ واقعی تلاش‌های انتشار حداقل نود دقیقه است. پست‌های بیش از یک بازه عقب‌افتاده منقضی می‌شوند تا بعد از قطعی کانال پر از پیام نشود.

نسخهٔ سوم شیوهٔ نگارش، پس از استقرار در اجرای زمان‌بندی‌شدهٔ بعدی، پیش‌نویس‌های منتشرنشده را یک‌بار بازنویسی می‌کند. اصلاح بازبینی‌شدهٔ پست بازی که کاربر معرفی کرده نیز فقط روی شناسهٔ ذخیره‌شدهٔ همان پیام منتشرشده اعمال می‌شود؛ پیام تازه یا تکراری ارسال نمی‌شود. کلیدهای محرمانهٔ موجود هنگام استقرار حفظ می‌شوند.

تلگرام کلید idempotency برای `sendMessage` ندارد. پیش از ارسال، قصد ارسال ثبت می‌شود؛ در قطع ارتباط با نتیجهٔ نامعلوم، ارسال خودکار تکرار نمی‌شود و وضعیت `unknown` نیازمند بررسی دستی است. تضمین «دقیقاً یک بار» در این مرز شبکه ممکن نیست.

## استقرار

به Node.js نسخهٔ ۲۴ یا بالاتر و Wrangler نیاز است:

```sh
npm test
npx wrangler login
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put ADMIN_TOKEN
npx wrangler deploy
```

حساب، کانال، مدل و ساعت در `wrangler.jsonc` تنظیم شده‌اند. `ADMIN_TOKEN` یک مقدار تصادفی بلند است و فقط برای مدیریت سرویس استفاده می‌شود. توکن‌ها در مخزن قرار نمی‌گیرند. بعد از استقرار اولیه، سرویس تا فراخوانی مسیر `start` متوقف است. در استقرار مجدد، وضعیت فعال بودن و صف حفظ می‌شوند.

## مدیریت

آدرس سرویس:

`https://ai-social-network.erfansa1997.workers.dev`

همهٔ مسیرهای مدیریتی به هدر `Authorization: Bearer <ADMIN_TOKEN>` نیاز دارند:

| روش | مسیر | کاربرد |
|---|---|---|
| GET | `/health` | سلامت پاسخ‌گویی سرویس؛ به معنی فعال بودن صف نیست |
| GET | `/admin/status` | وضعیت فعال بودن، صف، متن‌ها، پیام‌های ارسال‌شده و خطاها |
| POST | `/admin/start` | فعال‌کردن جمع‌آوری و انتشار |
| POST | `/admin/pause` | توقف جمع‌آوری و انتشار |
| POST | `/admin/tick` | اجرای یک نوبت پردازش با رعایت زمان و جلوگیری از تکرار |
| POST | `/admin/ai-check` | آزمون کوتاه اتصال مدل |
| POST | `/admin/rewrite-pending` | بازنویسی مطالب منتشرنشده؛ فقط وقتی سرویس متوقف است |
| POST | `/admin/recurate` | بازچینی مجموعهٔ فعلی با حفظ پیام‌های ارسال‌شده و ساعت‌های باقی‌مانده؛ ابتدا توقف لازم است و پردازش در پس‌زمینه آغاز می‌شود |

این ربات ناشر کانال است و به پیام خصوصی `/start` پاسخ نمی‌دهد. برای کنترل از API مدیریتی استفاده کنید.
